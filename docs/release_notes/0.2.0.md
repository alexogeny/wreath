# v0.2.0

_Released 2026-08-11._

Wreath's first compiled-authority release. The portable framework and server
core now have one implementation: the C code shipped in the wheel. Python is
the public facade where an API needs one, not a second runtime selected by a
request-time branch.

Installation is also explicit. `uv add wreath` installs the portable native
wheel for Linux, macOS, or Windows. Linux deployments can add the io_uring
reactor with `uv add 'wreath[linux]'`; HTTP/3 is selected with
`uv add 'wreath[h3]'` or its `http3` alias.

## Breaking

- A compiled wheel is required. A damaged installation missing `_core`,
  `_client`, `_edge`, `_server`, or `_postgres` now fails at import and names
  the missing component; there is no Python fallback or native/pure selector.
- `wreath.orm.model.ListModel` is removed. Generated native model storage is
  the model storage implementation.
- The remaining public and internal native/pure selection flags, fallback-only
  branches, and parity terminology are removed.

## Added

- Native wheels for CPython 3.14 on Linux x86-64 and ARM64, macOS Intel and
  Apple silicon, and Windows x86-64. Every wheel is installed and serves a real
  HTTP request on its native GitHub runner before a release can be created.
- `wreath[linux]`, a Wreath-owned Linux companion wheel containing the io_uring
  reactor and its pinned OpenSSL build; the portable base wheel remains free of
  Linux-only code.
- `wreath[h3]` and `wreath[http3]`, aliases for the HTTP/3 companion wheel. It
  contains Wreath's QUIC extension and bundles pinned OpenSSL, ngtcp2, and
  nghttp3 libraries with their license texts.
- First-class policy compilation, second-factor authentication, OAuth, SSO,
  tenancy and infrastructure controls, workflows, MCP, gRPC, generic protobuf,
  temporal and geospatial types, and PostgreSQL extension types including
  half-precision and sparse vectors.
- Cross-module `wreath port` analysis for models, inheritance, sessions,
  queries, migrations, routes, jobs, settings, and foreign API references,
  with expanded Flask, Bottle, aiohttp, Pyramid, Tornado, Django,
  FastAPI/Pydantic, ormar, and SQLModel recognition.

## Changed

- Ed25519 and P-256 arithmetic, signing, DKIM canonicalization, HTTP
  signatures, AES-GCM dispatch, and JOSE helpers use fixed-width in-tree C with
  no mandatory third-party runtime dependency.
- GraphQL parsing, staged projection, relationship layout, and direct result
  JSON output are compiled operations. The HTTP path no longer materializes an
  intermediate Python result tree.
- Protobuf descriptors compile once and drive direct object encoding and
  decoding. OTLP traces, metrics, and logs write protobuf directly from
  projector state.
- ORM model cells and bitmaps use generated C storage. Hydration, identity
  deduplication, join assembly, and relationship attachment use
  operation-local native state rather than Python working sets.
- Flight projection, recording reads, Prometheus rendering, SCIM parsing, gRPC
  unframing, multipart streaming, and SQL placeholder renumbering now own their
  repeated work and private state in C.
- Shared native writers and extension-local HTTP/header units keep the portable
  extensions independent of Linux-only reactor code.

## Fixed

- PostgreSQL decode and pipeline paths avoid repeated Python work and preserve
  response keep-alive decisions through the HTTP client.
- Required extensions refuse broken installations at import instead of
  allowing a later `None` branch to fail during a request.
- Release publication cannot create a tag until the portable and companion
  wheels build, install, import, and serve successfully.

## Performance

Retired userspace instructions were measured on repeated pinned workloads, so
the results are not inferred from laptop wall-clock time.

| Workload | Before | After | Reduction |
| --- | ---: | ---: | ---: |
| Flight mixed ingest, 192 cells | 14.33M | 0.215M | **98.5%** |
| DKIM relaxed body, 276 KiB | 112.12M | 4.78M | **95.7%** |
| gRPC unframe, 192 messages | 1.300M | 0.092M | **92.9%** |
| OTLP metrics, 128 routes | 16.25M | 1.83M | **88.7%** |
| WFR1 read, 4,096 cells | 9.99M | 1.46M | **85.4%** |
| GraphQL cold parse, 240 fields | 5.433M | 1.859M | **65.8%** |
| Generic protobuf decode, 48 records | 13.371M | 4.881M | **63.5%** |
| ORM joined hydration | 3.162M | 1.422M | **55.0%** |
| GraphQL projection and JSON | 3.026M | 1.629M | **46.2%** |
| TechEmpower Fortunes request | 156.65k | 109.11k | **30.4%** |

The already-small static request stayed near its floor, moving from 23.01k to
22.77k instructions. The complete request trace fell from 129 to 115 native
events while retaining two Python frames; all fourteen removed crossings were
handler-phase glue.

## Docs & internals

- Complexity contracts cover 118 probes with same-size controls: 11 constant
  and 107 linear, with no marked defects.
- Native ownership, error-sentinel, GIL, build-freshness, map, and complexity
  linters cover the compiled authority boundary.
- The default source build remains dependency-free. The OpenSSL/ngtcp2/nghttp3
  inputs exist only inside explicitly selected companion wheel builds, are
  pinned, and carry their upstream license texts.
