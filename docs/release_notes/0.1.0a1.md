# v0.1.0a1

_Released 2026-07-28._

The first public alpha. Wreath is a Python 3.14-first ASGI framework that ships
its own HTTP server, PostgreSQL driver, ORM, migration stack, and documentation
generator, with no mandatory runtime dependencies. It runs behind any conforming
ASGI server; the native pieces are optional accelerations of the same behaviour.

This is an alpha because the server has not yet finished fuzzing, sanitizer,
soak, and security review. The framework API is usable; treat the server tiers
as experimental and pin the version.

## Added

- **The framework.** Routing, binding and validation, dependencies, the
  middleware pipeline and its built-ins, OpenAPI and typed client generation —
  no Pydantic, no SQLAlchemy, no third-party runtime dependency.
- **A native HTTP server** speaking HTTP/1.1 and HTTP/2, with an optional HTTP/3
  build. Available as a deployment tier, not a requirement.
- **The metal tier** (`--loop metal`): an io_uring event loop that owns listener
  acceptance, receives, sends, signals, timers and generic readiness, with a
  native hashed timing wheel in place of asyncio's timer heap. Multi-worker
  through `--workers` on an `SO_REUSEPORT` listener group.
- **PostgreSQL end to end** — wreath's own driver, ORM, and a migration stack
  generated from the live catalog rather than from authored migration files,
  with schema-image diffing, drift detection, artifact verification, and
  transactional application under an advisory lock.
- **Deferred migrations.** A conversion is declared beside the model and guarded
  by a predicate scan that refuses ordered comparison on a column mid-conversion.
  Reverting a completed recode is refused rather than silently reported as done.
- **Partial indexes**, `Index(where=...)`, round-tripping through the catalog
  without spurious drift.
- **Durable jobs and messaging** on PostgreSQL, including long mutations via
  `jobs.launch` — the job id is the task id, seeded `queued` so an immediate poll
  is not a 404, and only the runner sets terminal state, because only it can tell
  a retry from a dead-letter.
- **Authentication and a built-in Cedar authorizer**, with no external
  dependency and a pure-Python twin held to byte-for-byte parity.
- **Calculated views.** `Series` and `Aggregate` declare chart data over one
  model: bucketed in the reader's timezone, every bucket present, per-measure
  fill, stable keys rather than ranks, and ceilings that refuse rather than
  truncate. Sealing settles a bucket once late data can no longer change it.
- **`wreath.store`, `wreath.queries`, and `ChunkedPass`** — one keyed-store
  primitive replacing six hand-written ones, and a table walk by keyset ranges
  with one transaction per chunk, paced so it does not starve request traffic.
- **GraphQL**, cross-worker cache invalidation, and an N+1 detector behind
  `wreath doctor`.
- **`wreath port`** — a FastAPI codemod that reads by static analysis only, never
  importing the application, and reports what it cannot translate rather than
  guessing.
- **`wreath audit`** — a zero-dependency WCAG 2.2 A/AA and performance ruleset
  over generated HTML, extended to check a live service's own responses.
- **`wreath docs`** — the site generator, building from typed Python config with
  no YAML and no third-party theme.

## Performance

- Bitset routing is the default; HTTP/2 and HTTP/3 defer building a request
  scope until a route is activated.
- Every cache on the request path has a ceiling, and native routing memory is
  released rather than retained for the process lifetime.
- Two io_uring experiments were **reverted after measurement** — registered ring
  descriptors and a transport ablation both failed to earn their keep. Nothing
  ships here on the strength of a plausible mechanism alone.

## Docs & internals

- **Twenty-five architecture decision records**, reconstructed from the code that
  implements them, plus the delivery-plan archive.
- **A canonical example** — a wildlife camera-trap network exercising every
  shipped feature against a real PostgreSQL. Building it is what found most of
  the defects closed before this release: `validate_schema="error"`, the default,
  had never once completed lifespan startup against a real database.
- **Complexity probes** as a gate: a hot path whose measured complexity class
  changes fails the build, so a regression is caught as a shape rather than as a
  slow benchmark.
- **A replay engine proved against its own recordings** — three container
  formats treated as untrusted input, and fault schedules held to recovery
  properties rather than to determinism alone.
- The benchmark harness measures the server rather than itself: one load-generator
  thread saturated below several of the arms it was measuring, so throughput is
  now generated across cores and every arm is held to the same worker count.
