# v0.3.3

_Released 2026-08-28._

Wreath 0.3.3 adds first-class request admission and deadline policies, moves the
default test and mutation workflow onto Wreath's native engine, and tightens
the authentication boundaries around audiences, browser sessions, OAuth
clients, and HMAC secrets. Existing applications using those authentication
surfaces need the migrations below; the new HTTP policies remain opt-in.

## Breaking changes

- `wreath test` now uses the native engine by default and refuses unsupported
  pytest fixtures, hooks, marks, plugins, or arguments during collection. Use
  `wreath test --engine pytest` where that compatibility surface is required,
  or `--engine dual` to compare collection and outcomes between both engines.
- `JwtVerifier` and `app.oidc_provider()` require an explicit audience. Pass the
  service audience, or pass `None` only when another layer performs the audience
  check. OIDC issuers must be absolute HTTPS URLs, and provider HTTP clients and
  discovered JWKS endpoints must share the issuer origin.
- OIDC and SAML login state is now bound to a non-empty browser session. Pass a
  stable `session_id` to `begin_login()` and the matching value at callback;
  SAML consumers must also return the exact `relay_state` minted for that login.
- Confidential `ClientRegistration` values require a client secret of at least
  32 bytes. Present it when redeeming authorization codes, using client
  credentials, or rotating client-bound refresh tokens. OAuth issuers must use
  HTTPS, and configured HMAC signing secrets must also contain at least 32 bytes.
- Object URL secrets, webhook HMAC keys, and retired session-cookie secrets now
  reject material shorter than 32 bytes. Rotate short development values to
  random secrets of at least that length before startup.

## Added

- `ConcurrencyPolicy`, `DeadlinePolicy`, and `MaintenancePolicy` provide
  fail-fast admission, async handler deadlines, and dynamically controlled
  maintenance windows with refusal counters.
- `RequestDecompressionPolicy` accepts one bounded gzip request member, while
  `SignedRoutePolicy` provides expiring, optionally single-use capabilities
  bound to the normalized method, exact path, and original query ordering.
- `SecurityHeadersPolicy` supports per-request CSP nonces and report-only mode.
  `CsrfPolicy` can accept an explicitly configured form field while retaining
  the header-only fast path.

## Changed

- OAuth refresh rotation preserves the original audience, scope, tenant, and
  client binding, enforces a configurable lifetime, and refuses attempts to
  widen the original grant.
- Native test collection is reused by mutation and fuzz work. Pytest remains an
  independent compatibility oracle rather than a silent fallback.
- File responses no longer hold an executor worker while a slow client drains
  the body. `HEAD` requests stat the same descriptor and emit the correct range
  headers without reading file contents, and static lookup admission is bounded
  before work enters its executor.

## Fixed

- OIDC discovery can no longer redirect JWKS loading across origins or hide
  credentials, queries, or fragments in the configured issuer.
- SAML RelayState and OIDC state now expire, remain single-use, and cannot be
  consumed from another browser session. Pending-login stores have explicit
  capacity bounds and reclaim expired entries.
- Cache invalidation, MCP subscriptions, room membership, and ORM dirty tracking
  use indexed ownership instead of repeated full scans, while cleanup removes
  stale subscriptions and descriptors deterministically.

## Performance

- On the documented broad default-marker workload, the native test engine used
  43.4% fewer retired userspace instructions than pytest and completed the same
  work 1.820 times faster across three interleaved warm runs.
- On the documented 60-control mutation corpus, native execution preserved all
  60 killed verdicts while retiring 97.9% fewer userspace instructions than the
  pytest path across seven interleaved runs.
- Direct XML canonicalization output, startup-prepared Cedar route facts, and a
  shared 1,000-route application image reduced their retained instruction
  workloads by 41.89%, 15.95%, and 13.21%, respectively, with exact output
  equivalence across seven interleaved runs per comparison.

## Docs & internals

- Complexity discovery now fingerprints unchanged source, distinguishes real
  nested linear work from set membership and iterator ownership, and reduces
  the acknowledged static candidate set from 1,776 shapes to two.
- Native operation-local kernels now serve test execution, mutation, duplicate
  scanning, source linting, and documentation analysis without adding a
  mandatory runtime dependency to the framework core.
