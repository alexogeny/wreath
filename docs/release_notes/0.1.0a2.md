# v0.1.0a2

_Released 2026-07-28._

A packaging fix. **v0.1.0a1 could not be installed by anyone** — its source
distribution was missing three C headers, so compiling the native extensions
failed immediately. Nothing about the framework changed; this release is the
same code in a distribution that actually builds.

## Fixed

- **The sdist now carries every build input.** Installing v0.1.0a1 failed with
  `fatal error: server_request_capi.h: No such file or directory`. Without a
  `MANIFEST.in`, setuptools shipped only the sources it could infer — each
  extension's `sources=` plus whatever its `depends=` happened to name — and that
  inference was incomplete twice over: `server_request_capi.h` and
  `server_hpack_huffman.h` were listed in no `depends=` at all, and the HTTP/3
  sources belong to an extension that is only configured under
  `WREATH_BUILD_HTTP3=1`, so a default build omitted them and the optional
  extension could not be built from the published sdist either.
- A stale `neo_asgi.egg-info/` directory, carrying the project's former name, is
  no longer shipped.

## Docs & internals

- The release workflow validates and orders versions with **PEP 440** rather than
  a semver regex and `sort -V`. The regex rejected `0.1.0a1` outright as invalid,
  and `sort -V` ordered `0.1.0 < 0.1.0-alpha` where PyPI orders it the other way
  — so the guard meant to prevent publishing the wrong thing disagreed with the
  index it was guarding.
- A release that fails partway can now be re-run. The tag it had already pushed
  used to block its own retry; the guard now distinguishes a reused version
  (refused) from an unfinished one (resumed), and prereleases are marked as such
  on GitHub instead of taking the "Latest release" badge.
- Per-version release notes are published to the documentation site. They were
  linked from the index but excluded from the build, so the first release to
  follow the documented process failed the docs gate on a dead link.
