# v0.3.1

_Released 2026-08-18._

Wreath 0.3.1 closes the integration gaps found while moving a large 0.2.1
application onto the current framework. It keeps request work in existing
native kernels and makes the new declaration, schema, and provenance surfaces
startup or orchestration-time Python.

## Added

- `CedarSchema` validates policy action names and nested context attributes at
  construction. Schema action groups become ordinary `Action` parent entities,
  so group membership continues through the native Cedar evaluator with no
  request-time schema walk.
- `wreath.provenance` signs stored artifacts independently of RFC 9421 HTTP
  Message Signatures. Its deterministic sidecar supports multiple Ed25519
  signatories, chained counter-signatures, signed quorums, and later byte-change
  detection using Wreath's native Ed25519 and SIMD base64url kernels.
- `CursorParams`, `CursorPage`, `cursor_params`, and `paginate_cursor` provide
  keyset pagination with primary-key tie-breakers and opaque, order-bound
  cursors. `app.objects(..., backend="memory")` now registers the complete
  development/test backend through the same application surface as local and
  S3 storage.

## Fixed

- Nested discriminated response unions now select and serialize their validated
  dataclass arm instead of handing a dataclass instance to the JSON encoder.
- Audit declarations install their append-only guard as schema step 2, including
  a statement-level `TRUNCATE` trigger; deployments no longer need separate DDL
  wiring.
- Object-store replay observation and fault coordinates cover streaming reads
  and writes, existence checks, listing, URL minting, and the original four
  operations.
- Invalid pagination sort/filter names are client-safe `400` problems that name
  the allowed form. In-app notifications call `RoomRegistry.broadcast`, and
  SKIP endpoint replay resolves protected routes without attempting to
  authorize them.
