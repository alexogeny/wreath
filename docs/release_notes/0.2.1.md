# v0.2.1

_Released 2026-08-13._

Wreath 0.2.1 is a backward-compatible performance release. No existing public
Python name is removed or renamed, and no existing call signature changes, so
applications written against 0.2.0 do not need a migration. The work is
primarily below the Python boundary: repeated collection, wire-format, policy,
and projection work now runs in operation-owned native kernels.

## Added

- `wreath.series.ChartData`, an immutable prepared numerical dataset that can
  reuse dense cells, presence bits, selection plans, and path buffers across
  several chart projections.
- `wreath.temporal.spine_lengths()`, which calculates several calendar
  cardinalities over one range while sharing the time-zone conversion and
  without materializing each spine.

These are opt-in additions. Existing one-shot series and temporal APIs remain
available with their existing signatures.

## Changed

- Shared native data kernels now own bounded collection and wire-format walks
  used by validation, codecs, recording and replay, logs and metrics,
  negotiation, sync snapshots, pagination, temporal and series projection, and
  Cedar evaluation.
- Request headers stay in request-owned native storage through lookup and
  policy evaluation, and are decoded only when the public `Request` API reads
  them.
- Successful Cedar route and batch decisions remain native; Python objects are
  materialized for denials, and principal entities are skipped when the active
  policy cannot read them.
- PostgreSQL sparse-vector codecs and `SparseVector` share operation-owned
  native storage without introducing process-global mutable state.
- Prometheus exposition, logging, Flight Recorder data, DNS, SigV4,
  JSON/protobuf, ORM hydration, geospatial processing, and related policy paths
  avoid repeated Python-side formatting and container walks.

## Performance

Retired userspace instructions were measured over repeated, pinned,
process-tree workloads. The deep declarative dashboard fell from **7.923M** to
**4.137M instructions per request**, a **47.79% reduction**.

| Re-measured workload | Before | After | Reduction |
| --- | ---: | ---: | ---: |
| Prometheus metrics | 649.1k | 322.6k | **50.30%** |
| Sync snapshot | 511.3k | 462.9k | **9.47%** |
| Enterprise Cedar route | 557.6k | 545.0k | **2.27%** |

Across the re-measured metrics, sync, and enterprise-Cedar subset, retired
instructions fell by **6.21%** in aggregate. The realistic request trace also
moved from 115 to 114 native calls and from 38 to 37 pre-activation native
calls, while retaining two Python frames.

## Verification & internals

- The holistic benchmark now exercises successful declared series, tenancy and
  organizations, generated admin, SCIM, sync, workflows, readiness,
  Prometheus, OpenAPI, signed webhooks, and persistent WebSocket rooms.
- The complexity catalog contains 118 controlled probes, each paired with a
  same-size control and with no marked defects.
- Focused coverage exercises prepared and one-shot chart projection, temporal
  cardinalities, Cedar compilation and batching, request-header retention,
  native framing and codecs, ORM storage, pagination, sparse vectors, logging,
  Prometheus exposition, and bounded sync snapshots.
